# 共有・招待の権限とチャット履歴

利用するアカウントを指定したい場合は**招待**、URLを知る人がログインせず利用できるようにする場合は**共有リンク**を選びます。どちらも講座の動画を視聴し、Q&AとStudyを利用できます。**受講者の質問は講座所有者のAI回答枠を使い、保存された会話は所有者が閲覧・CSV出力できます。**

招待を受けるには、招待先と一致する確認済みメールアドレスのアカウントでログインし、承認します。招待を送っただけでは参加者になりません。共有リンクは転送できるため、所有者が最初にURLを送った相手だけに利用を限定するものではありません。

## 利用経路ごとの権限 {#permissions}

通常のアプリとAPIで講座を利用する場合の表です。「招待参加者」は、招待を承認したアカウントを指します。同じ人が参加資格と共有リンクの両方を持つこともあり、リクエストで使った経路によって扱いが変わります。

| 操作 | 講座所有者 | 招待参加者 | 共有リンク利用者 |
|---|---|---|---|
| 講座を開き、講座内の動画を再生 | ログインして利用可 | ログインして利用可 | 現在のリンクで利用可。ログイン不要 |
| Q&Aで質問 | 可 | 可 | 可 |
| Studyで学習 | 利用可能なPLOGがあれば可 | 利用可能なPLOGがあれば可 | 利用可能なPLOGがあれば可 |
| 講座の編集・削除、動画の追加・削除・並べ替え | 可 | 不可 | 不可 |
| 元動画・字幕・PLOGの編集 | 動画所有者のみ | 参加資格では許可されない | リンクでは許可されない |
| 招待・参加者・共有リンクの管理 | 可 | 不可 | 不可 |
| 他の人の質問を含む、保存済み講座チャット履歴の閲覧 | 可 | 不可 | 不可 |
| 講座チャット履歴のCSV出力・削除 | 可 | 不可 | 不可 |
| 招待された講座からの退出 | メンバー管理で対象者を削除 | 自分の参加資格から退出可 | 退出する参加資格なし |

再生できるのは講座に含まれる動画です。所有者の動画ライブラリー全体や、元動画の編集画面へのアクセス権を与えるものではありません。Studyには、準備完了で利用可能な[学習グラフ](../plog/README.md)も必要です。チャットの権限があっても、グラフが利用できるとは限りません。

招待参加者とリンク利用者は、現在のチャット画面の回答を読めますが、保存済み講座履歴を読み直したり、自分の過去の質問だけを履歴APIから取得・出力したりすることはできません。所有者が見られる履歴にはQ&AとStudyのやり取りが含まれます。画面の会話表示、保存済みチャット履歴、Studyの一時的な進捗は別のデータです。

## 講師Aの講座に受講者Bが質問する例 {#usage-and-history}

講師Aが所有する講座の招待を受講者Bが承認し、ログイン後の講座画面で質問した場合です。

1. APIはBのアクセス権を確認し、回答前に**Aの**AI回答枠を1件予約します。B自身の枠は減りません。Studyにも適用され、保存済みの最初の問いを返す場合も対象です。
2. Aは保存された質問と回答を**履歴**で閲覧・CSV出力でき、質問者としてBのユーザーID・ユーザー名・メールアドレスを確認できます。他の参加者はその履歴を取得できません。
3. Bが共有URLから質問した場合もAの枠を使いますが、履歴は共有由来となり、履歴・CSVの質問者欄は空になります。Bがログイン済みでも同じです。どのリンク利用者が質問したかは示しませんが、Bが質問本文へ書いた情報は保存され、Aが読めます。

利用枠はAのアカウントに計上するリクエスト全体で共用し、受講者・講座ごとに分けた枠ではありません。AのAI回答数が上限に達すると、A自身・招待参加者・リンク利用者を含め、Aの枠を使う新しいQ&A・Studyを受け付けなくなります。Aのアカウントが容量超過で制限されている場合も同様です。この判定自体が参加資格を取り消したり、講座の閲覧・利用可能な動画の再生を止めたりするわけではありません。

APIは生成前に利用枠を予約し、回答を完了できなかった場合は予約の返却を試みます。講座や表示済みの回答を読むだけでは、新しいAI回答枠を予約しません。所有者の枠が残っていても、別のレート制限で一時的にリクエストを断る場合があります。[利用枠の実装](https://github.com/yukiharada1228/videoq/blob/main/apps/api/src/repositories/quota-repository.ts)と[チャット処理](https://github.com/yukiharada1228/videoq/blob/main/apps/api/src/features/chat/message-service.ts)を参照してください。

## アクセスの取り消しと履歴の保持 {#removing-access}

| 所有者の操作 | 利用できなくなるもの | 残るもの |
|---|---|---|
| 保留中の招待を取り消す | その招待の承認 | 他の参加資格、共有リンク、既存のチャット履歴 |
| 承認済みの参加者を削除 | その参加資格による新しい講座取得・チャット | 有効な共有リンクからは引き続き利用可。以前の質問は所有者の履歴・CSVに残る |
| 共有リンクを無効化 | そのリンクによる新しい講座取得・チャット | 所有者・招待参加者のアクセス、以前の共有由来の質問 |
| 別の共有スラッグを保存 | 旧URLはその講座と一致しなくなる | 新URLでの利用、参加資格、既存の履歴 |
| 講座のチャット履歴を削除 | 保存済みの質問・回答・フィードバックと回答評価を削除 | 講座の権限・参加資格。Studyの進捗リセットではない |

招待の取り消しは**保留中**の招待に対する操作です。承認後は参加者を削除してください。参加者を削除しても別の共有リンクは無効にならず、リンクを無効化しても招待参加者は残ります。リンクを知っている人の両方の利用経路を止めたい場合は、その人の参加資格を削除し、必要に応じてリンクも無効化・変更します。

アクセス変更は新しいリクエストで判定します。取得済みのコピー・CSV・画面の会話を回収するものではなく、すでに許可された回答処理は完了する場合があります。発行済みの動画再生URLも利用できる場合があります。S3互換ストレージの再生URLは発行から1時間有効で、外部動画URLには別のアクセス規則があります。また、スラッグの変更は旧スラッグを永久に使用禁止にするものではなく、再利用すると旧URLが再び有効になり得ます。[メディアURLの実装](https://github.com/yukiharada1228/videoq/blob/main/apps/api/src/integrations/media.ts)も参照してください。

参加者の削除やリンクの無効化では、チャット履歴を**削除しません**。保存済みの会話を消したい場合は、所有者が講座のチャット履歴削除を別途実行します。特定の参加者だけでなく講座全体の履歴を削除する操作であり、出力済みのCSVなどは消えません。

## 方式を選び、共有して確認する {#walkthrough}

1. 自分が所有する講座を開きます。含まれる動画を確認し、質問と回答を所有者が読めることを受講者へ伝えます。
2. アカウントを指定する場合は**メンバー管理**でメールアドレスを入力し、招待を送ります。受信者はメールのリンクから、招待先と一致する確認済みメールアドレスでログインし、**招待を承認して参加**を押します。参加者一覧を確認します。公開リンクを使う場合は**共有**でスラッグを保存し、URLをコピーします。
3. 選んだ方式に合わせ、別の受講者アカウントまたはログアウトしたブラウザーで確認します。動画再生とチャットができ、講座編集や保存履歴の操作は表示されないことを確認します。新しいQ&A・Studyの応答は所有者の枠を使います。
4. 所有者として**履歴**を開き、必要ならCSVを出力します。招待参加者の質問には質問者情報があり、リンクの質問は共有由来として表示されます。所有者が読んでよい確認用の質問を使ってください。
5. 使った経路に合わせて参加者を削除、またはリンクを無効化し、再読み込みと新しいリクエストで失効を確認します。開いたままの動画・チャット画面だけでは、現在も許可されているかは分かりません。別の経路が残る場合は、上の表を確認してください。
