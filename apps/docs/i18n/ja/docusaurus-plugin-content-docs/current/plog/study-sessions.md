# Studyの再開・期限・やり直し

Studyの一時的な進捗は、**進捗の保存成功から12時間**有効です。ページを開く、回答を読む、モードを切り替える、通常のQ&Aを送る操作では延長しません。アカウント全体の恒久的な学習記録ではなく、翌日に続けられるかは残り時間とブラウザーの状態によります。

## 3種類のデータの違い

| データ | 含むもの | 消去・置換する操作 |
|---|---|---|
| 画面の会話表示 | 現在のチャット画面の発言、直前の問い | 再読み込み、画面からの離脱、Q&A／Study切り替え、**最初からやり直す** |
| 保存済み講座チャット履歴 | Studyを含む質問と回答。所有者が履歴・CSVで取得できる | 別の講座履歴削除操作。やり直しでは削除しない |
| Studyの一時的な進捗 | 学習中の概念、修得済みの概念、ヒント位置、直近の進行用判定 | 期限切れ。**最初からやり直す**と、このタブ・利用経路で新しい空の進捗を使う |

画面の会話は保存履歴から復元しません。再読み込み・モード切り替え後の送信でも、学習中の概念を引き継ぐ場合があります。採点にはクライアントが送った直前の問いを使い、なければ概念に保存された最初の問いを参照します。何に答えていたか分からない場合は**最初からやり直す**を使ってください。「続ける」だけの送信も学習の1ターンとなり、判定やヒントに影響する場合があります。読み取り専用の状態確認ではありません。

## 何が継続するか

継続には、ブラウザーが持つ同じ識別情報、同じサーバー上の利用主体・講座、有効期限内の進捗が必要です。アプリは講座または共有リンクごとの識別情報を `sessionStorage` に保存し、解答や判定自体はそこへ保存しません。

| 場面 | 画面の会話 | 一時的な進捗 |
|---|---|---|
| 同じタブで再読み込み | 消える | 識別情報が残り、期限内なら、次のStudy送信で継続 |
| ウィンドウ幅の変更、端末の回転、モバイルの動画一覧・プレーヤー切り替え | 会話、下書き、選択中のモード、受信中の回答を同じ画面内で保持 | **最初からやり直す**の後も現在の識別情報を保持。これらの表示変更では保存期限を延長しない |
| Study → Q&A → Studyと切り替え | 切り替えるたびに消える | 保持。Q&Aでは保存期限を延長しない |
| 講座から離れ、同じタブで戻る | 新しい画面になる | 同じ条件を満たせば、その講座の進捗を継続できる |
| 回答待ちの間に別の講座・共有リンクへ切り替える | 前の回答の受信を中断し、会話と下書きを消去。切り替え先では入力できる | 移動先のセッションを使用。元の利用経路へ戻れば識別情報は維持する。受信の中断はサーバー側の進捗保存を取り消す操作ではない |
| 保存領域を引き継がない新しいタブ、別ブラウザー、別端末 | 新規 | 新規。ログインだけでは同期しない |
| タブ複製、開いた元のタブの保存領域がコピーされる場合 | 新しい画面になる | 同じ識別情報を持つ場合があり、サーバー上の進捗を共有し、互いの操作で進むことがある |
| ログイン後の講座画面から、公開共有ページへ移る | 新しい画面になる | ブラウザーの保存キーが別。共有ページでログインしても、通常の講座画面の進捗には切り替わらない |
| ログイン後の講座画面でアカウントを変更 | 新しいアカウントの権限が適用される | サーバー上の利用主体が変わり、同じブラウザーの識別情報でも前のアカウントの進捗は引き継がない |
| Studyの保存成功がないまま保存期限に達する | 表示済みの会話は残る場合がある | 失効。次の成功したターンは空の進捗から開始 |
| タブ・ブラウザーを閉じる | 画面は閉じる | 継続は保証しない。ブラウザーのセッション復元で識別情報が残っても、サーバーの期限は延長しない |

タブを開く・復元する挙動はブラウザーによって異なります。[MDNのsessionStorageの説明](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)も参照してください。保存領域の複製は最初のコピーであり、継続的な同期ではありません。開いたタブの片方でやり直しても、もう片方が持つ識別情報は更新しません。

ブラウザーの保存領域が拒否・容量不足になった場合は、開いているチャット画面内だけで識別情報を保持し、注意を表示します。画面を開いている間は続けられますが、再読み込みで継続できなくなったり、新しい識別情報の保存に失敗していた場合は以前の進捗に戻ったりする可能性があります。

## 状態を確認して、最初からやり直す

1. 利用可能な講座で**学習**（Study）を選びます。送信前は「次の送信時に確認」と表示し、ブラウザーに識別情報があるだけで進捗の保存済みとは判定しません。
2. ターンが成功すると、**新しい進捗で開始**したか、**保存済みの進捗を継続**したかと、サーバーが確認した保存期限をブラウザーの現地時刻で表示します。新規には初回と以前の進捗が利用できなくなった場合を含みます。
3. 最後に確認した期限を過ぎると、次の送信での確認を案内します。複製した別タブで新しく保存している場合もあるため、最終判定はサーバーが行います。通信切断やターン失敗時は未確認の表示となります。応答の配送が失敗する前に、サーバーの進捗保存が完了している場合もあります。
4. やり直す場合は**最初からやり直す**を押し、説明を読んで確定します。この画面の会話と入力中の文章を消し、この講座・利用経路の識別情報を変えます。キャンセルすれば保持します。この操作自体はチャットを送信せず、AI回答枠を使いません。
5. 学びたい内容を送信します。次のターンは空の進捗を使い、以前の返答の採点やヒント位置を引き継ぎません。指定した概念の前提から始める場合もあり、全動画の最初の概念を必ず選ぶ操作ではありません。

応答処理中はやり直しボタンを無効にします。保存済みチャット履歴、別の講座や別タブの進捗、PLOGの内容は削除しません。使わなくなった古い進捗には元の期限が適用されます。その識別情報を持つ別タブが使い続ければ、期限も延長できます。履歴の削除は別の操作です。

## APIと保存先の区別

`chat.send` では `studySessionId`、SSEのリクエストでは `study_session_id` を指定します。成功したStudy応答には `study_session: { status: "started" | "continued", expires_at: <Unixミリ秒> }` を含められます。SSEでは `done` に載せます。進捗のコミットとチャット応答の保存が成功してから返します。識別情報を省略したStudyはリクエストごとに空の進捗を使い、このメタデータを返しません。Q&AもStudyメタデータを持ちません。メタデータのない旧API応答を受け取った場合は未確認と表示します。

サーバーは識別情報を利用主体・講座に紐付けます。通常のログイン後の講座利用では質問者、共有経由ではログイン済みでも講座所有者が利用主体になります。識別情報はアクセス権の代わりにはならず、各リクエストで講座の権限を確認します。同じ識別情報のターンはリースとリビジョンで直列化し、期限の確認は取得時にも行うため、削除用アラームが遅れても期限を超えた進捗は使いません。[Study処理](https://github.com/yukiharada1228/videoq/blob/main/apps/api/src/lib/plog-study.ts)と[StudySessionの保存処理](https://github.com/yukiharada1228/videoq/blob/main/apps/api/src/durable-objects/study-session.ts)を参照してください。

`plog.resetLearnerState` は、動画所有者本人の、その動画に属する `learner_concept_states` のDB行を削除し、件数を返す別のAPIです。現行StudyのDurable Objectを参照・リセットしません。**最初からやり直す**の代わりに使わず、`deleted: 0` をStudyの進捗がない証拠として扱わないでください。[resetLearnerStatesの実装](https://github.com/yukiharada1228/videoq/blob/main/apps/api/src/repositories/plog-repository.ts)を参照してください。
